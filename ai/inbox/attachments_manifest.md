## 1. 附件一：GCL功率测试基准（V2.1）26.03.26 (1).xlsm——副本.xlsm

### 1.1 文件用途

这是功率预测模型样例文件，不是普通业务明细表。

该文件包含多个版型 Sheet，每个 Sheet 内部通过不同配置项计算组件功率档位分布。

配置项包括但不限于：

1. 焊带选型。
2. 玻璃选型。
3. 电池厂家。
4. 电池尺寸。
5. 面积。
6. 标准差。
7. 线缆长度。
8. 汇流条。
9. 标板基准。

选择不同配置后，Excel 中的：

1. 电池效率区。
2. 各功率档百分比。
3. 组件预测模型档位分布。
4. 电池产出分布。

会自动变化。

### 1.2 对开发的要求

必须注意：

1. 不能把该 Excel 简单当成静态数据表导入。
2. 不能只读取现有公式结果就认为完成。
3. openpyxl 不执行 VBA，也不能可靠重算 Excel 公式。
4. 必须审计 Excel 结构、公式、宏依赖和核心计算逻辑。
5. 必须明确哪些数据入库，哪些逻辑由后端计算引擎复现。
6. 后续需要支持周期性导入新版本 Excel。
7. 每次导入都必须生成新的模型版本。
8. 智能问答默认使用当前 active 功率模型版本。
9. 不能将当前 Excel 的某一组结果 hardcode 到代码中。
10. 不允许让 LLM 直接读 Excel 后自由回答功率预测结果。

### 1.3 需要重点分析的内容

1. 所有 Sheet 名称。
2. 每个 Sheet 对应的组件版型。
3. 上方配置选择区。
4. 配置项和配置选项。
5. 配置选项对应的功率影响值。
6. 电池效率区。
7. 供应商效率分布区。
8. 功率档位范围。
9. 组件预测模型档位分布。
10. 标板基准数据。
11. 核心计算公式。
12. VBA / 宏是否参与核心计算。
13. 后端复现计算逻辑的方案。
14. 抽样校验方案。

### 1.4 使用边界

1. 当前文件是模型样例，不是长期唯一版本。
2. 后续系统必须支持新版本功率预测 Excel 导入。
3. 不要将附件直接作为正式业务数据导入。
4. 当前文件用于分析模型结构和公式逻辑。
5. 生产链路应使用模型版本管理和 active 版本机制。

## 2. 附件二：BOM配置搭配问询：.docx

### 2.1 文件用途

这是业务问题样例文件，用于理解业务员希望怎么提问，以及系统应该支持哪些问答类型。

该文件只作为：

1. 问题类型参考。
2. 自然语言问法参考。
3. 槽位结构参考。
4. 答案展示格式参考。

### 2.2 重要说明

非常重要：

1. 文档中的版型号是假的。
2. 文档中的订单号是假的。
3. 文档中的评审号是假的。
4. 文档中的项目名是假的。
5. 文档中的问题不能直接作为真实验收问题。
6. 文档中的问题不能 hardcode。
7. 不能为了让文档里的问题通过而伪造数据。
8. 不能将文档中的假问题写成固定测试基线。

正式测试必须：

1. 基于当前项目中真实存在的 BOM 数据。
2. 基于实际导入的功率预测模型。
3. 自行生成真实可执行测试题。
4. 使用后端确定性计算结果作为答案来源。
5. 测试题和预期结果必须可追溯。

### 2.3 该文档体现的问题类型

该文档主要体现三类问题。

#### 第一类：BOM 配置查询类

例如：

1. 某订单的玻璃、间隙贴膜、焊带、汇流条、接线盒规格是什么？
2. 两个订单的材料有哪些不一致？
3. 多个订单的核心材料配置生成表格。

这类问题主要依赖：

1. plan_bom_header
2. plan_bom_material_line

#### 第二类：功率预测类

例如：

1. 某版型、某配置、某标板下，各家供应商效率段在哪里？
2. 指定供应商需要使用哪个效率段？
3. 某配置是否能满足目标功率档比例？

这类问题依赖：

1. 功率预测模型。
2. 供应商效率分布。
3. 功率档位计算。
4. 目标比例匹配。

#### 第三类：BOM + 功率预测混合类

例如：

某订单 + 目标功率档 + 目标比例 → 推荐供应商和效率段。

处理链路：

```text
自然语言问题
↓
识别订单 / 评审号 / 项目名
↓
查询 BOM
↓
抽取核心材料配置
↓
映射到功率预测配置项
↓
调用功率预测引擎
↓
返回供应商、效率段、功率档位分布、匹配度
```

## 3. 测试题生成要求

由于样例文档中的数据是假的，必须基于真实数据生成测试题。

生成测试题时需要：

1. 从 plan_bom_header 中找真实存在的订单。
2. 从 plan_bom_material_line 中提取该订单的核心材料配置。
3. 判断这些配置能否映射到功率预测模型。
4. 结合 active 功率模型版本生成可计算问题。
5. 保存测试题和基线结果。
6. 不能使用样例文档中的假单号、假项目名、假版型作为真实验收数据。

建议后续生成测试文件：

1. backend/app/domains/plan_bom/config/plan_power_acceptance_questions.json
2. backend/app/domains/plan_bom/config/plan_power_acceptance_baseline.json

测试题至少覆盖：

1. 订单 + 目标功率 + 目标比例。
2. 明确配置 + 各家供应商。
3. 明确配置 + 指定供应商。
4. BOM 配置无法映射。
5. 无 active 模型版本。
6. 供应商无有效效率分布。
7. 版型无法识别。
8. 目标功率档不在模型范围内。
9. 同义问法。
10. 假单号无法命中时的正确拒答 / 追问。
