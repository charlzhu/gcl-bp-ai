# 物流 903 问答系统领导汇报版

## 一、项目背景

物流业务日常会频繁查询发运量、运费、车次、承运商、区域、省份、客户、任务状态等数据。过去这类问题通常依赖人工查表、临时取数或反复确认口径，响应慢、口径不稳定，也不便于沉淀复用。

本阶段围绕物流一期，先把“结构化数据问答”做成可试运行能力：业务人员用自然语言提问，系统判断能否回答、是否需要补充条件，或者是否暂时不能回答并解释原因。

## 二、当前解决了什么问题

当前系统已经把物流题库从“只有样例题”推进到“按 A/B/C 状态治理”的试运行状态：

- 能直接回答的问题，进入 A 类，按受控查询链路回答。
- 条件不清楚的问题，进入 B 类，先追问，不乱算。
- 当前不能回答的问题，进入 C 类，明确说明原因和可改问方向。

这意味着系统不是简单匹配固定题目，而是按问题意图、缺失条件、数据边界和业务口径进行判断。

## 三、当前总体成果

当前 903 条物流样例题的正式处理结果：

- `A = 656`：可以直接回答。
- `B = 178`：需要追问、补槽、业务确认或数据口径确认。
- `C = 69`：不能回答，但可以解释原因和改问方向。
- `D = 0`：当前没有待修订标准答案类。

已完成的验收基础：

- 真实用户验收样例集：`85/85`。
- 前后端联调闭环检查：`9/9`。
- 903 全量真实问法语义回归：`1559/1559`。
- NLU Center dry-run：`122/122`。
- A 类关键题精确断言：`20/20`。
- A 类基础行为回归：`75/75`。
- C 类拒答边界复检：`69/69`。

## 四、核心亮点

1. 不依赖固定原题。
   系统不是只会回答题库原文，而是通过真实问法语义回归验证了同义表达、口语表达和业务表达。

2. 支持真实问法。
   用户可以说“26 年 1 月发了多少 MW、多少车”，也可以说“1 月份物流总出货规模和总车数是多少”，系统会尽量归一到同一类受控查询。

3. 能主动追问。
   如果问题缺时间、指标、区域、客户、承运商、运输方式、车型、异常定义或评价标准，系统会先追问，而不是直接给不可靠结果。

4. 不能回答时不会乱答。
   对预测、ETA、开放讨论、原因诊断、未建模口径、系统无数据支撑的问题，系统保持拒答边界。

5. 能解释无法回答原因。
   C 类问题不会显示成系统故障，而是说明为什么当前不能回答，以及用户可以怎么改问。

6. 前后端已具备试运行基础。
   前端已覆盖成功、追问、拒答、空结果、错误、加载和边界输入态。

## 五、典型问答示例

### 1. A 类直接回答示例

输入：

> 2026 年 1 月总发运量是多少 MW？总共发了多少车次？

系统应该展示：

- 查询成功。
- 返回发运量、车次等结构化结果。
- 展示数据范围、查询口径和查询计划。

讲解口径：

> 这是当前系统最稳定的场景。问题包含时间、指标和数据范围，系统可以直接通过受控查询链路回答。

### 2. B 类追问示例

输入：

> 最近物流成本是不是变高了？

系统应该展示：

- 需要补充条件。
- 追问统计时间范围，例如近 30 天、某个月或某季度。
- 追问比较基准，例如同比、环比或与历史均值比较。
- 追问成本口径，例如总运费、单瓦成本或平均费用。

讲解口径：

> 这类问题业务上很常见，但“最近”“变高”都不够明确。系统不会直接猜，而是先把需要补充的条件问清楚。

### 3. B 类补槽后回答示例

第一问：

> 哪个承运商表现最差？

系统应该追问：

- 请确认评价指标，是按总运费、签收率、任务量、单瓦成本还是异常率。
- 请确认时间范围和排序规则。

补充后输入：

> 按 2026 年 1 月各承运商签收率从低到高排序。

系统应该展示：

- 查询成功。
- 返回承运商签收率排名。

讲解口径：

> 原问题不能直接答，但补齐指标、时间和排序规则后，就可以进入受控查询。

### 4. C 类拒答解释示例

输入：

> 预测下个月物流费用会是多少？

系统应该展示：

- 当前暂不支持。
- 说明当前系统只回答已发生数据统计，不编造预测值。
- 给出可改问方向，例如“2023-2025 年各月物流总费用是多少”或“2026 年已发生月份运费是多少”。

讲解口径：

> 这是系统边界控制。当前没有预测模型和预测验收口径，所以系统不会给看似合理但不可验证的答案。

### 5. 空结果解释示例

输入：

> 2026 年 1 月某个不存在省份的总运费是多少？

系统应该展示：

- 问题识别成功。
- 在现有数据范围内没有查到符合条件的结果。
- 建议检查省份、时间或筛选条件。

讲解口径：

> 空结果不是系统故障，而是查询条件下没有数据。页面会给出清晰解释。

## 六、当前边界

当前不能直接回答的问题主要包括：

- 预测类：未来费用、趋势、波动区间。
- ETA 类：预计到达时间、在途到货时间。
- 原因诊断类：为什么异常、为什么费用高、责任归因。
- 开放讨论类：治理方案、管理建议、规则设计。
- 数据缺口类：当前系统没有字段或历史数据不覆盖。
- 业务定义缺口类：异常、最差、风险、达标、效率等标准未定义。

不能直接回答的原因：

- 没有可验证数据。
- 业务口径未确认。
- 当前未开放受控 query_key。
- LLM 不允许查数、生成 SQL 或代替业务判断。

需要业务确认的内容：

- 指标口径。
- 异常和风险定义。
- 评价标准和阈值。
- 数据字段是否存在。
- 是否需要新增数据来源。

## 七、试运行建议

建议先小范围试运行：

- 选择物流业务、计划经营、数据 owner 等少量用户。
- 先围绕发运量、运费、车次、承运商、区域、省份、客户、任务状态开展试用。
- 收集真实用户问法，不要求用户按题库原题提问。
- 每条反馈按 A/B/C/Bug/Data/Biz 分类闭环。
- 每周复盘一次，优先处理高频、高价值、口径明确的问题。

试运行阶段的目标不是追求全量直答，而是做到：

> 该答的答准，不清楚的追问，不能答的解释原因。
