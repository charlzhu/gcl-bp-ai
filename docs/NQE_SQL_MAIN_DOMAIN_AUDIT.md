# NQE 四大业务域正式链路只读审计

> 审计范围：本轮只读查看当前仓库代码、NQE 主指令/主报告、物管状态文件和附件参考资料。本文档不把物管状态文件作为 NQE 事实源，不覆盖原状态文件。

## 1. 审计结论总览

| 业务域 | 当前正式链路状态 | NQE 可替换性 | 主要风险 | 建议阶段 |
|---|---|---|---|---|
| 物流 | 成熟正式链路；统一业务问数入口已覆盖物流；NL2SQL/shadow/assist 基础存在 | 高 | 不能破坏既有全量回归；需保证用户可见回答不泄露技术细节 | 第一替换域 |
| 计划 BOM | 独立 QA、查询、候选消歧、对比、replay 能力成熟 | 中 | 候选消歧、compare/replay 不适合一次性 SQL 化 | 第三替换域 |
| 功率预测 | 作为计划 BOM 子能力，有确定性预测引擎 | 低到中 | LLM 不能直接计算预测；必须保留 PowerPredictionEngine | 第四替换域 |
| 产销存/经营分析 | 独立 endpoint/service，前端与业务问数入口仍分流 | 中到高 | 指标口径需完整沉淀，缺数据场景要业务化处理 | 第二替换域 |

## 2. 当前已完成能力判断

1. 已有统一 Graph 原型：包含领域路由、关键词提取、多路召回、SQL 生成、EXPLAIN 校验、修正、执行和终端节点。
2. 已有 Pydantic 召回实体抽象：字段、指标、取值实体可作为 nqe_* 元数据模型设计参考。
3. 已有 Milvus 与 rapidfuzz 基础：可支撑字段/指标向量召回和取值模糊匹配。
4. 已有统一业务问数流式入口：当前正式入口主要服务物流与计划 BOM。
5. 已有前端 BusinessChatPage：可复用模式切换、流式输出、结果表格、空结果/错误展示等经验。
6. 已有物流、BOM、产销存和功率预测测试目录与业务基线，可作为 NQE 回归基础。

## 3. 当前未完成能力判断

1. 统一 SQL Agent 尚未成为正式主入口。
2. 当前正式入口仍存在物流/BOM/产销存分流，产销存仍使用独立 API。
3. 当前 SQL 原型安全门不足：只做 EXPLAIN 不够，缺少 SELECT-only、白名单、系统库禁止、LIMIT、超时、单语句、危险函数等硬校验。
4. 当前 NQE 元数据知识库尚未形成独立 nqe_* 表体系。
5. 当前四域 metadata / metric / value / rule 覆盖尚未全量闭环。
6. 当前 trace / query log / replay / shadow compare 没有按 NQE 统一模型闭环。
7. 当前存在历史非 NQE 命名和注释痕迹，后续必须清理并迁移到内部命名。
8. 当前附件参考资料尚未转化为 gcl-bp-ai 内部 NQE 设计资产；不能直接复制命名或部署参数。

## 4. 本次任务与当前仓库状态是否一致

一致。本轮 NQE-SQL-MAIN-0 要求只读审计、总体设计、建看板；当前仓库已有足够的 Graph、业务域、前端与测试基础可审计，但仍不具备直接切换正式链路的安全条件。

## 7. 物流域审计

| 项 | 当前情况 |
|---|---|
| 当前入口 | 统一业务问数流式入口已处理物流模式；前端 BusinessChatPage 可调用 |
| 当前服务 | 物流 QA service、query planning、NL2SQL shadow/assist、catalog recall 等均存在 |
| 当前测试 | 物流 NL2SQL、business_qa_graph、业务验收样例均已有基础 |
| NQE 化方式 | 先接入 shadow，再 assist，最后 on；旧服务保留 fallback |
| 可 SQL Agent 化 | 聚合、排序、筛选、年度/月度对比、路线费用、车次、基地/客户/承运商维度查询 |
| fallback 必须保留 | 复杂组合问法、旧回归不一致场景、业务化表达兜底、历史 query_key 对照 |
| 风险 | 物流已有强基线，任何改动都必须跑全量回归；均价等业务口径不能被 AVG 明细误替代 |

## 9. 功率预测子能力审计

| 项 | 当前情况 |
