# 试运行反馈闭环方案

## 用户反馈字段

| 字段 | 说明 |
| --- | --- |
| 反馈日期 | 用户提交反馈的日期 |
| 提问人 | 反馈人姓名 |
| 部门 | 所属部门 |
| 模块 | 物流数据问答 / 计划 BOM 问答 |
| 原始问题 | 用户完整提问文本 |
| 系统返回状态 | A / B / C / 错误 |
| 系统返回摘要 | 系统给出的主要结论或追问 |
| 是否满意 | 是 / 否 / 部分满意 |
| 问题分类 | 见下方分类 |
| 期望答案 | 用户认为应返回什么 |
| 业务口径说明 | 如涉及口径，请写明业务定义 |
| 是否需要补数据 | 是 / 否 |
| 是否需要产品优化 | 是 / 否 |
| 处理结论 | 待处理 / 已修复 / 需确认 / 暂不支持 |
| 负责人 | 跟进人 |

## 问题分类

- A 答错：系统直接回答了，但结果、口径、范围或展示不符合业务预期。
- B 追问不好：系统要求补充条件，但追问不清楚、不自然或没有指出关键缺口。
- C 拒答不合理：用户认为当前数据或规则可以回答，但系统拒答。
- 数据问题：源数据缺失、字段错误、订单或材料未入库。
- 业务口径问题：需要业务确认“核心材料”“复用”“异常”“是否一致”等定义。
- 前端体验问题：页面展示、表格、上传、loading、错误态影响使用。
- 系统 Bug：接口异常、页面报错、上传失败、返回结构异常。

## 处理流程

1. 收集反馈：业务同事按模板提交原始问题和系统返回。
2. 初筛分类：产品或业务接口人按 A/B/C/Bug/Data/Biz 分类。
3. 数据核对：数据问题先核对源 Excel、数据库和导入报告。
4. 口径确认：业务口径问题先由业务负责人确认定义。
5. 工程修复：明确可工程化的问题进入小步修复。
6. 回归验证：修复后进入对应模块回归脚本。
7. 周会复盘：每周汇总新增、关闭、待确认和暂不支持问题。

## 每周复盘机制

- 每周固定汇总一次试运行反馈。
- 统计 A 答错、B 追问不好、C 拒答不合理、数据问题、业务口径问题、前端体验问题、系统 Bug 数量。
- 对能快速修复的问题安排当周修复。
- 对需要业务确认的问题形成确认清单。
- 对暂不支持的问题同步不支持原因和改问方式。

## 责任人建议

- 业务负责人：确认口径、优先级和正确答案。
- 数据负责人：确认源数据质量、缺失字段和导入问题。
- 产品负责人：判断反馈分类、整理试运行看板。
- 工程负责人：修复可工程化问题并执行回归。

## 可以快速修的问题

- 明确 alias 缺失。
- 明确槽位抽取遗漏。
- 明确展示文案不清楚。
- 明确前端错误态或 loading 问题。
- 已有数据和服务能力但编排未接好的问题。

## 必须业务确认的问题

- “核心材料”“关键辅材”等业务定义。
- “是否复用”“是否异常”“是否合理”等判断口径。
- BOM 版本选择规则。
- 物流异常判定阈值。
- 功率倒推、电池方案等需要工艺或产品规则的问题。

## 不能马上支持的问题

- 当前数据不存在的问题。
- 需要预测模型的问题。
- 需要外部系统实时状态的问题。
- 需要人工业务判断或策略制定的问题。
- 会让 LLM 直接编造事实、规格或统计结果的问题。
