# LOGISTICS_B_LONG_CLARIFICATION_ROUND3

## 一、本轮目标

本轮继续推进《B-长期澄清池 Round3》，目标不是把问题强行推进进 A，而是把更多原本只会落入通用澄清的问题，升级成：

- 规则层先锁定 clarification 边界
- LLM 只做缺口径识别
- LLM 只做业务化追问候选生成
- 补充后再回到现有受控 data-qa 主链路

本轮继续坚持：

- 不让 LLM 改写 `clarification / success / unsupported` 最终边界
- 不扩前端
- 不扩 RAG / Agent
- 不碰 BOM
- 不直接进入经营分析代码开发

## 四、本轮新增的澄清能力

### 1. comparison_basis_scope

适用问题示例：

- `2023-2025区域发运份额变化最大的区域是哪一个？`
- `不同承运商的派车状态分布是否存在明显差异？`
- `哪些省份更偏好铁路运输，哪些省份几乎全部使用公路？`

当前追问重点：

- 比较指标是什么
- “变化最大 / 明显差异 / 更划算 / 最忙”按什么标准判断

### 2. mapping_consistency_scope

适用问题示例：

- `将“公路/汽运”口径统一后，2023-2025公路类运输的发运件数占比是多少？`
- `物流公司、物流供应商、承运商三种问法在系统里是否映射为同一字段口径？`
- `哪些任务在主任务表已是SIGNEDFOR，但派车解析结果parsed_is_signed=0？应如何判定状态冲突？`

当前追问重点：

- 哪个字段 / 哪张表作为主口径
- 要统一后的统计结果，还是先看冲突明细

### 3. route_metric_scope

适用问题示例：

- `2023-2025期间，620W产品发往新疆的平均路程是多少？`
- `2023-2025单价/车最高的前10条线路是什么？`
- `2024年合肥基地17.5车平均单车运费是多少？`

当前追问重点：

- 到底是看平均单车运费、平均单瓦价，还是平均路程
- 平均值按车次、按任务，还是按筛选后的线路记录计算

### 4. data_consistency_scope

适用问题示例：

- `哪些记录存在日计划发运件数为空或为0，但日实际发运件数大于0？`
- `2026年是否存在同一手机号关联多个司机姓名的情况？`
- `2026年assign_detail中extra_cost大于0但cost_proof_url为空的记录有多少条？`

当前追问重点：

- 看问题数量、问题率，还是异常明细
- 是否继续按承运商、仓库、状态或省份拆分

## 五、LLM 在 Round3 的使用边界

本轮继续严格保持：

- LLM 可以做：
  - 缺口径识别
  - 追问候选生成
- LLM 不可以做：
  - 最终边界裁决
  - 把 `clarification` 改成 `success`
  - 把 `clarification` 改成 `unsupported`

也就是说，Round3 仍然是：

> 规则层锁边界，LLM 只增强追问质量。

## 七、当前判断

Round3 完成后，可以明确说：

1. `B-长期澄清池` 的治理已经从 Round1 / Round2 继续扩展到 Round3；
2. 当前业务问法不再按死板 `exact match` 判定是否澄清；
3. 规则层继续锁住最终边界；
4. LLM 已经在长期澄清题里稳定承担“缺口径识别 + 业务化追问候选生成”的辅助角色；
5. 当前更适合继续做 `B-长期澄清池` 的后续治理，而不是优先扩 `C-边界观察池` 的能力边界。
