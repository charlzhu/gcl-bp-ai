# 物流域 Top200 高价值 B 题工厂化 Round4

## 一、Round4 目标

Round4 继续沿用已经验证有效的工厂化推进方式：

- 题族聚类
- 能力矩阵
- 批量收口
- 自动回归

本轮不再回到逐题挤牙膏模式，而是针对 Round3 后剩余的 `9` 条高价值 B 题，统一按题族做正式裁决：

- 能稳定支持的，正式推进进 A
- 仍缺口径的，继续保留在 B
- 已确认超边界的，正式转入 C

---

## 二、Round4 选择的题族

本轮共选择 `7` 个题族、`9` 条题：

1. 2026 月度承运商总运费类（2 条）
2. 2026 月度单瓦成本类（1 条）
3. 客户 / 项目总运量与项目地分析类（2 条）
4. 区域 / 年度运量综合与拆分类（1 条）
5. 历史线路 / 城市运价分析类（1 条）
6. 异常 / 相关性分析类（1 条）
7. 2026 系统状态 / 排名 / 诊断类（1 条）

选择原因一致：

- 都是 Top200 中剩余的高价值 B 题
- 当前已经不适合再逐题处理
- 需要一次性把“能支持 / 继续澄清 / 正式转 C”的边界压实

## 三、Round4 对应的能力包

本轮实际落地的能力点主要有 `3` 组：

### 1. 2026 基地经营过滤总运费能力包

支持：

- `合肥基地 / 阜宁基地`
- 指定月份
- 指定客户或承运商
- 2026 系统总运费统计

对应 query_key：

- `sys_total_fee_by_filters`

本轮新增口径：

- 统一按 `dwd_logistics_ship_task.base_code` 过滤基地
- 目前正式放行：
  - `合肥基地 -> base_code=1`
  - `阜宁基地 -> base_code=2`

说明：

- 这一步把 `RAW052`、`RAW056` 从 B 收进口径稳定的 A
- 同时修正了系统侧“基地过滤题如果命中 MW 主链路会误算全量”的隐形风险

### 2. 系统侧基地过滤发运量安全修正

支持：

- 2026 基地发运量 MW 题带基地过滤执行

对应 query_key：

- `sys_mw_and_trip_count`

说明：

- 本轮不是把所有基地经营题全部纳入 Round4 统计
- 但系统侧已经不再忽略基地过滤条件，避免出现“问合肥基地却返回全量 MW”的错误行为

### 3. supplier_price 诊断边界正式转 C

本轮明确固化：

- `supplier_price` 分布
- 高价离群点
- 离群点集中在哪些任务或承运商

当前统一进入：

- `C 类不支持`

原因：

- 这类问题本质上属于诊断分析 / 离群点识别
- 当前一期结构化统计主链路不应假装支持

## 七、自动回归情况

本轮已经形成独立的 Round4 工厂化回归脚本与报告：

- 脚本：`scripts/logistics_top200_b_factory_round4.py`
- 报告：`tmp/logistics_question_bank/logistics_top200_b_factory_round4_report.json`

该脚本会：

1. 读取 Top200 正式清单
2. 扣除已经在 P1/P2、Round1、Round2、Round3 中推进进 A 或转入 C 的题
3. 自动选择 Round4 题族
4. 真实调用当前 `data-qa` 主链路
5. 输出每题状态、题族汇总和 A/B/C 变化

## 九、当前结论

Top200 高价值 B 题的工厂化推进已经从 Round1、Round2、Round3 延续到 Round4。

当前已经稳定形成：

- 题族聚类
- 能力矩阵映射
- 题族级批量收口
- 自动回归验证

Round4 的价值不是大量新增 A，而是把剩余高价值 B 题进一步压缩，并把本来不该继续停在 B 的诊断题正式转入 C。  
下一轮可以继续沿用同一套工厂化骨架推进 Round5，不需要回到逐题推进模式。
