# FRONTEND_V2_NEXT_STAGE_CANDIDATES.md

## 一、文档用途

本文件记录前端 V2 收口完成后，下一阶段可进入的候选任务列表。

注意：

- 本文件只列建议，不代表已排期
- 任何新任务开始前，仍应先审查当前仓库实际状态

---

## 二、下一阶段候选任务

### 1. 前端 V2.1 稳定性补强

建议优先聚焦：

- 固定 console error 修复
- 条件查询页解释与后端契约进一步统一
- 查询历史分页与关键词检索
- 前后端联调回归清单沉淀

说明：

- 这是最贴近当前状态的下一步
- 成本可控
- 对联调效率和试运行稳定性提升最直接

### 2. 查询历史进一步增强

可选增强方向：

- 高级筛选
- 详情信息分区展示继续优化
- 历史问题回放链路补强

### 3. 条件查询页进一步增强

可选增强方向：

- 契约统一后去掉前端兼容提示
- 更细的筛选体验优化
- 条件组合回显优化

### 4. compare 场景专项回归

可选增强方向：

- 对比结果解释专项验证
- 差值、差异率和左右值展示一致性验证
- 空结果与单边有结果场景回归

### 5. fallback 语义专项收口

可选增强方向：

- 全面检查 fallback 输出字段
- 继续消除可能误导业务的名称映射
- 补更细粒度日志标记

### 6. 试运行准备

可选增强方向：

- 联调操作说明
- 最小试运行说明
- 页面使用说明
- 问题回放说明

---

## 三、当前不建议立即进入的方向

当前不建议直接跳到：

- 图表与大屏
- 复杂领导演示版 UI
- Excel 导出
- 多域统一前端重构
- 新业务域前端扩展

原因：

- 当前更需要先把稳定性、契约一致性和联调闭环继续做扎实
- 过早扩展范围会稀释当前 V2 已经形成的收口成果

---

## 四、推荐排序

建议顺序：

1. 前端 V2.1 稳定性补强
2. 查询历史进一步增强
3. compare 与 fallback 后端专项收口
4. 试运行准备
5. 更复杂的演示版与可视化建设
