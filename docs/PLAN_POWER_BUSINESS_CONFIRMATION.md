## 2. 公式口径确认

### 2.1 已确认公式策略

业务已确认采用：

```text
formula_policy = semantic_fixed_mode
```

含义：

1. 后端计算引擎不完全照搬 Excel 原文件中的疑似公式复制错误。
2. 对 `R30:R34` 中疑似把 `I行` 错写为 `L行` 的公式，后端按公式语义修正。
3. 后续系统结果以 `semantic_fixed_mode` 为正式口径。
4. Excel 原始公式仅作为源文件审计对象和差异追溯依据，不作为该疑点的最终计算准则。

### 2.2 语义修正规则

旧版 M1 审计中发现的疑似形态如下：

```excel
R30 = NORMSDIST((I30-$R$28)/B15) - NORMSDIST((L30-$S$28)/B15)
```

语义修正后应按以下模式计算：

```excel
R30 = NORMSDIST((I30-$R$28)/B15) - NORMSDIST((I30-$S$28)/B15)
```

通用规则：

```text
R行 = CDF((I行 - R28) / B15) - CDF((I行 - S28) / B15)
```

其中：

```text
CDF(x) = standard_normal_cdf(x)
```

后端建议实现：

```python
normal_cdf(x) = 0.5 * (1 + erf(x / sqrt(2)))
```

### 2.3 新版 Excel 补充审计结论

新版 `26.04.13 TOPCon` 文件中，`R30:R34` 疑似问题仍未完全消失：

| Sheet | 疑似单元格 | 原始公式状态 | 系统处理口径 |
|---|---|---|---|
| `NT12R-66GDF` | `R30` | 第二段仍引用 `L30-$S$28` | 按 `I30-$S$28` 语义修正 |
| `NT12R-66GDF` | `R32` | 第二段仍引用 `L32-$S$28` | 按 `I32-$S$28` 语义修正 |

因此后续系统仍需要 `semantic_fixed_mode`。M2 解析器应记录原始公式 issue；M3 计算引擎应按本文件口径执行语义修正。

## 6. 后续系统默认口径

1. 当前 active 功率模型初始目标为新版：`GCL功率测试基准（V2.1）TOPCon 26.04.13.xlsm`。
2. 后端不得执行 Excel VBA；必须把宏逻辑和公式链翻译成确定性代码。
3. `formula_policy` 默认且唯一上线口径为 `semantic_fixed_mode`。
4. M2 应保存原始公式、source cell、parse issue 和 `formula_policy`。
5. M3 应按 `semantic_fixed_mode` 计算，不允许让 LLM 直接计算功率分布。
6. M4 BOM 映射应优先使用本文件确认的别名口径，并保留 `source_material_line` 追溯。
7. `BOM配置搭配问询：.docx` 仍只作为题型和问法参考，不能作为真实测试数据，不能 hardcode。
8. 无法映射的配置必须返回 `unresolved_items`，不得编造。

## 7. 对 M2 的准入影响

业务口径已足以支撑 M2：功率模型版本化入库。

M2 需要把以下字段纳入模型版本或解析结果：

1. `formula_policy = semantic_fixed_mode`
2. `source_file_name`
3. `source_file_hash`
4. `business_version_label`，例如 `TOPCon 26.04.13`
5. 每个 Sheet 的原始名与 normalized model code
6. 每个配置项和选项的原始单元格位置
7. 标板原始表头与标准归一名称
8. 解析 warning / error，尤其是 `R30/R32` 语义修正 issue

结论：M1.5 后建议进入 M2，但 M2 只做模型版本化入库和解析校验，不实现正式计算引擎、不接入 QA、不改前端。
