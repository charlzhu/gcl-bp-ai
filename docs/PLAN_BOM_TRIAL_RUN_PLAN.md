# PLAN_BOM_TRIAL_RUN_PLAN

## 试运行目标

验证计划 BOM 问答在真实业务提问中的可用性、边界清晰度和反馈闭环效率。

## 试运行范围

- 已导入的 `BOM 源数据.zip` 数据范围。
- 当前核心五类材料：玻璃、间隙贴膜、焊带/互联条、汇流条、接线盒。
- 当前 `BOM问题.xlsx` 覆盖的意图类型和真实变体问法。

## 试运行用户

- 计划经营人员
- 采购协同人员
- 产品/BOM 维护人员
- 业务负责人指定的试点用户

## 上传 BOM 流程

1. 打开计划 BOM 页面。
2. 选择单个 `.xls/.xlsx/.xlsm` 文件上传。
3. 系统返回解析结果、材料行数、warning 和 next_action。
4. 上传成功后进入 QA 提问。

## 提问流程

1. 输入自然语言问题。
2. 系统返回 A/B/C 状态。
3. A 类直接查看答案、表格或对比结果。
4. B 类按追问补充订单、版本、材料或范围。
5. C 类查看不支持原因和可改问方向。

## 反馈分类

- A：回答正确且可直接使用。
- B：需要追问或补充条件。
- C：当前无法回答但解释清楚。
- Bug：系统异常、展示错误或接口错误。
- Data：源数据缺失、订单版本不完整、字段解析问题。
- Biz：业务定义、复用口径、功率倒推规则等需要确认。

## 每周复盘机制

- 汇总用户原始问题和系统返回状态。
- 标记高频 B 类和高价值 C 类。
- 区分可工程化项、数据补齐项、业务口径确认项。
- 只在确认口径后推进，不盲目迁 A。

## 成功标准

- A 类问题稳定命中，事实不被 LLM 修改。
- B 类追问能让用户知道补什么。
- C 类解释清楚，不造成系统故障感。
- 上传和 QA 接口稳定，无 500。
- 真实反馈能被分类并进入闭环。
