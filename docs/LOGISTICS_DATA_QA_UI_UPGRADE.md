# 物流 data-qa 前端 UI 体验升级说明

## 一、本轮目标

本轮将物流 data-qa 页面从偏表单/后台管理式页面，升级为更干净清爽的单列对话式页面。

本轮只改前端 UI、布局、交互体验和文档，不修改后端 A/B/C 判定逻辑，不新增 query_key，不继续迁 A，不让 LLM 查数、生成 SQL 或改写 B/C 边界。

当前正式总账仍为：

- `A = 656`
- `B = 178`
- `C = 69`
- `D = 0`

## 二、改动页面

本轮主要改动：

- `frontend/src/views/logistics-data-qa/LogisticsDataQaPage.vue`

该页面对应路由：

- `/logistics/data-qa`

相关接口仍复用现有：

- `frontend/src/api/logistics.ts`
- `frontend/src/api/logistics.js`

## 三、新布局说明

### 1. 顶部极简栏

页面顶部只保留必要操作：

- 折叠/展开主菜单；
- 页面标题“物流数据问答”；
- “历史记录”入口。

页面内不再重复展示 logo、试运行说明、能力分布或大段介绍，避免和左侧系统导航重复。

### 2. 主体对话区

页面主体改为更接近 ChatGPT 式的单列对话体验：

- 用户问题以右侧浅灰气泡展示；
- 系统回答以左侧简洁文本/卡片展示；
- 保留充足留白；
- 结果、追问、拒答、空结果、错误各自有独立视觉层级；
- 口径、数据范围、技术详情默认弱化，不抢业务答案。

### 3. 空会话

空会话只展示一句引导：

- “想查什么物流数据？”

已删除推荐卡片、能力说明、演示推荐、业务原则等介绍型模块。

## 四、各状态展示说明

### 1. 成功态

A 类问题会展示：

- 回答摘要；
- 数据表格；
- 行数提示；
- 数据范围；
- 口径说明；
- 可折叠的技术详情。

技术信息例如 query_key、query_plan 等继续保留在折叠信息中，不作为业务页面主文案。

### 2. 追问态

B 类问题会展示“需要补充信息”的温和提示：

- 明确告诉用户还需要补充什么条件；
- 继续展示后端返回的 `clarification_questions`；
- 前端额外提供可点击的补充建议 chips；
- chips 只负责把补充示例填入输入框，不直接执行查询，也不改变 A/B/C 裁决。

追问表达面向业务人员，避免直接暴露 slot、planner、guardrail 等技术词。

### 3. 拒答态

C 类问题会展示“当前暂不支持”的解释卡：

- 展示不能回答的业务原因；
- 展示可改问方向；
- 避免表现成系统错误；
- 不让用户误以为系统故障。

最终 unsupported 裁决仍由后端规则和边界策略决定，前端只负责展示。

### 4. 空结果态

空结果会展示：

- “查询成功，但当前条件下暂无数据”；
- 建议用户调整时间、区域、客户、承运商等条件；
- 避免空白页或误判为接口错误。

### 5. 错误态

错误态会展示友好错误卡：

- 不暴露技术堆栈；
- 提示稍后重试或联系维护人员；
- 保持页面可继续输入。

### 6. 加载态

加载态保持对话式反馈：

- 显示系统正在理解并查询；
- 发送按钮进入禁用态；
- 防止重复提交；
- 对话区不明显跳动。

## 五、推荐问题 chips

首页推荐问题 chips 已移除，避免页面显得拥挤和模板化。

B 类追问态仍保留“补充建议”小 chips，用于帮助用户组织下一次补充提问；这些 chips 不会直接执行查询，也不会改变后端 A/B/C 裁决。

## 六、响应式说明

本轮优先保证桌面端和常见笔记本分辨率的演示效果：

- 宽屏：单列对话区居中；
- 中屏：保持消息流和输入框优先；
- 小屏：气泡、表格和输入框自适应。

未新增大型 UI 依赖，继续使用 Vue3 + Element Plus 和页面局部 scoped 样式。

## 八、已知限制

- 本轮不新增后端能力，不改变 A/B/C 判定结果；
- 本轮不新增复杂前端页面；
- 本轮不做正式 UI 设计稿级像素还原；
- 技术详情仍可查看，但默认弱化；
- 页面内不再重复展示公司 logo，继续使用外层系统导航中的品牌区；
- 正式公司 VI、字体、色板如需严格落地，后续需要提供品牌设计规范。
