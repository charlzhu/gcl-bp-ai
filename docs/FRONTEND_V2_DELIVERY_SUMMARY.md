## 四、当前未完成但已知的边界

### 1. 条件查询页解释仍是前端兼容生成

当前条件查询页直连的是后端 `aggregate` 接口。

当前已确认：

- 后端可稳定返回 `execution_mode / summary / items / filters`
- 但不会像 `NL_QUERY` 那样完整返回：
  - `status`
  - `result_explanation`
  - `no_result_analysis`

因此当前页面上的部分状态与解释，是前端根据现有返回结构做的最小兼容生成。

### 2. 固定 console error 仍存在

当前前端页面加载后，Playwright 仍能观察到 1 条固定 console error。

当前判断：

- 不阻塞主链路联调
- 但属于前端稳定性问题
- 应在下一阶段专项处理

### 3. 查询历史页暂无分页与高级筛选

当前历史页已满足第一轮联调和问题回放，但仍不具备：

- 分页
- 关键词检索
- 更细粒度高级筛选

### 4. fallback 全量语义收口未纳入本轮

本轮只修正了已确认会误导前端展示的关键问题，不代表 fallback 语义已做全量专项清理。

## 五、前端 V2 依赖的后端接口

### 1. 自然语言查询

- `POST /api/v1/logistics/nl2query/parse-and-query`

前端依赖返回：

- `question`
- `parsed`
- `query_result`
- `response_meta`

### 2. 条件查询

- `POST /api/v1/logistics/query-service/aggregate`

前端当前依赖返回：

- `execution_mode`
- `query_type`
- `metric_type`
- `source_scope`
- `summary`
- `items`
- `filters`

### 3. 查询历史列表

- `GET /api/v1/sys/query/log`

前端当前依赖返回：

- 历史问题
- 查询类型
- 执行模式
- 模板命中
- 状态码
- 结果数

### 4. 查询历史详情

- `GET /api/v1/sys/query/log/{log_id}`

前端当前依赖返回：

- `parsed`
- `query_result`
- `response_meta`
- `execution_binding`
- `execution_summary`
- `request_payload_json`

## 六、当前适用场景

前端 V2 当前适合用于：

- 前后端联调
- 业务试用
- 第一轮演示
- 问题回放
- 查询结果解释与排查

- 大规模正式运营版
