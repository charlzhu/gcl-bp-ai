## 四、后续资料变更建议顺序

如果后续业务、数据或 SAP 资料发生变化，建议按以下顺序更新：

1. 先更新 owner 或确认人是否变化。
2. 再更新数据源和字段字典。
3. 再更新业务规则口径。
4. 再更新问题集和标准答案。
5. 最后更新 Go / No-Go 预评估。

这样可以避免字段未确认时先改问题集，或规则未确认时先进入开发。

## 七、资料变更后的重评方式

发生以下情况时，应重新评估 Go / No-Go：

- SAP 视图字段与当前字段字典不一致。
- 业务修改核心材料映射。
- 业务修改当前版本判定规则。
- 业务要求把功率预测提前到一期。
- 导出要求突破 500 行单文件上限。
- owner 或确认链路发生变化。

重评建议步骤：

1. 检查变更是否影响硬门槛。
2. 检查是否影响问题集标准答案。
3. 检查是否影响数据源切换规则。
4. 检查是否影响导出边界。
5. 给出继续 Go、Conditional Go 或 No-Go 的新结论。
