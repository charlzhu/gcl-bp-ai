# 物流 903 试运行业务反馈表模板

## 一、使用说明

本模板用于收集物流数据问答试运行期间的真实用户问题、系统表现和业务反馈。

填写原则：

- 尽量保留用户原始问题，不要改写成标准题。
- 如果用户不满意，请写明期望答案或业务口径。
- 如果涉及数据或口径，请标明是否需要业务 owner 或数据 owner 确认。

## 二、反馈表字段

| 字段 | 填写说明 |
| --- | --- |
| 提问人 | 填写用户姓名 |
| 部门 | 填写所属部门 |
| 提问时间 | 填写实际提问时间 |
| 用户原始问题 | 保留用户真实原话 |
| 系统返回状态 | 可选：查询成功 / 需要补充条件 / 当前暂不支持 / 未查到结果 / 查询失败 |
| 用户认为是否满意 | 可选：满意 / 基本满意 / 不满意 / 不确定 |
| 问题类型 | 可选：答案错误 / 没答出来 / 追问不清楚 / 数据不对 / 口径不清 / 不该拒答 / 应该拒答但系统回答了 / 其他 |
| 期望答案 | 用户认为应该返回什么 |
| 业务口径说明 | 业务上如何定义该问题、指标、异常、风险、排序或比较标准 |
| 是否需要新增数据 | 可选：是 / 否 / 不确定 |
| 是否需要产品优化 | 可选：是 / 否 / 不确定 |
| 处理结论 | 可选：已解决 / 进入 A 优化 / 保持 B 追问 / 保持 C 拒答 / 数据确认中 / 业务口径确认中 / 暂不处理 |
| 负责人 | 后续处理负责人 |
| 完成时间 | 处理完成时间 |

## 四、问题类型说明

- 答案错误：系统回答了，但数值、口径或维度明显不对。
- 没答出来：用户认为应能回答，但系统没有给出结果。
- 追问不清楚：系统追问表达不够业务化，用户不知道该补什么。
- 数据不对：业务认为底层数据或字段存在问题。
- 口径不清：业务定义、统计口径或评价标准未统一。
- 不该拒答：用户认为系统应该支持该问题。
- 应该拒答但系统回答了：系统越界回答，需优先修复。
- 其他：无法归入上述类型。

## 五、处理分类建议

- A：应直接答，进入查询能力或回归优化。
- B：应追问，优化追问模板或补槽闭环。
- C：应拒答解释，优化拒答原因和可改问方向。
- Bug：系统错误，进入缺陷修复。
- Data：数据问题，提交数据 owner。
- Biz：业务口径问题，提交业务 owner。
