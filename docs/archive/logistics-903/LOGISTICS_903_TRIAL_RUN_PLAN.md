# 物流 903 问答系统试运行执行方案

## 一、试运行目标

本次试运行目标是验证物流数据问答是否能在真实业务场景中稳定做到：

- A 类问题直接回答并答准。
- B 类问题先追问，补齐条件后继续回答。
- C 类问题明确拒答并解释原因。
- 前端能稳定展示成功、追问、拒答、空结果、错误和加载状态。

试运行不是追求全量直答，而是验证系统是否能稳定兜住真实问题。

## 二、试运行范围

当前试运行范围限定在物流一期：

- 历史 Excel 数据：2023-2025 年。
- 正式系统数据：2026 年后。
- 已开放结构化查询能力。
- 当前 903 总账治理结果：`A=656 / B=178 / C=69 / D=0`。

暂不纳入：

- 经营分析域。
- RAG 文档问答。
- Agent 自动任务。
- BOM 主链路。
- 预测模型和 ETA 估算。

## 三、试运行用户建议

建议首批用户控制在小范围：

- 物流业务负责人。
- 计划经营部使用人员。
- 数据 owner。
- 一线经常查物流数据的业务同事。
- 1-2 名产品或项目跟进人员。

建议人数：`5-15` 人。

## 四、试运行入口

入口：物流 data-qa 自然语言问答页。

使用方式：

1. 用户直接输入物流业务问题。
2. 系统返回查询结果、追问或拒答解释。
3. 用户根据系统追问补充时间、指标、区域、客户、承运商等条件。
4. 对不满意或异常结果填写反馈表。

## 五、用户使用流程

1. 输入原始业务问题。
2. 查看系统状态：
   - 查询成功；
   - 需要补充条件；
   - 当前暂不支持；
   - 未查到结果；
   - 查询失败。
3. 如果系统追问，按提示补充条件后再问。
4. 如果系统拒答，查看原因和可改问方向。
5. 如果用户认为结果不对，提交反馈表。

## 六、问题反馈流程

1. 用户记录原始问题和系统返回状态。
2. 用户说明是否满意。
3. 用户补充期望答案或业务口径。
4. 项目组按反馈类型分类。
5. 每周汇总并形成处理清单。
6. 可工程化的问题进入小步优化；需要业务确认的问题先确认口径；无数据支撑的问题保持拒答边界。

## 七、反馈问题分类

### A：应直接答

问题条件清楚，当前应命中受控查询并返回结果。

处理方式：

- 复核 query_key。
- 补充回归样例。
- 必要时修复 planner、slot 或 service。

### B：应追问

问题缺时间、指标、维度、比较基准或业务口径。

处理方式：

- 优化追问表达。
- 补充真实问法语义回归。
- 验证用户补槽后是否能回答。

### C：应拒答解释

问题属于预测、ETA、开放讨论、原因诊断、未建模口径或无数据支撑。

处理方式：

- 保持拒答边界。
- 优化业务可理解解释。
- 给出可改问方向。

### Bug：系统错误

接口报错、页面异常、展示错乱或导出失败。

处理方式：

- 记录 trace、问题、时间和截图。
- 按缺陷优先级修复。

### Data：数据问题

数据缺失、字段为空、系统未同步、历史数据覆盖不足。

处理方式：

- 提交数据 owner 确认。
- 明确是否补数据、补字段或保留边界。

### Biz：业务口径问题

异常、风险、达标、最差、效率等定义不清。

处理方式：

- 由业务 owner 确认定义、阈值、比较基准和输出粒度。
- 确认后再决定迁 A、留 B 或转 C。

## 八、每周复盘机制

建议每周固定复盘一次：

- 汇总本周用户提问总量。
- 统计 A/B/C/Bug/Data/Biz 分类数量。
- 选出高频问题。
- 对 A 类错误优先修复。
- 对 B 类高频追问优化表达。
- 对 C 类高频拒答优化原因说明。
- 对 Data/Biz 问题提交业务或数据 owner 确认。
- 更新回归样例和验收样例集。

## 九、风险控制

试运行必须保持以下边界：

- 不让 LLM 查数。
- 不让 LLM 生成 SQL。
- 不让 LLM 改写 B/C 边界。
- 不确定就追问。
- 无数据支撑就解释原因。
- 不把预测、ETA、开放讨论包装成结构化查询结果。
- 不把业务口径未确认的问题硬迁 A。

## 十、试运行成功标准

试运行可视为成功的标准：

- 用户能用自然语言提出真实物流问题。
- A 类问题能够稳定回答。
- B 类问题能够给出清楚追问。
- 用户补充条件后，能回答的问题可以继续闭环。
- C 类问题能明确说明为什么不能回答。
- 前端不出现 A/B/C 状态展示阻断问题。
- 每周反馈能被分类、复盘和持续优化。

核心验收口径：

> 该答的答准，不清楚的追问，不能答的解释原因。
