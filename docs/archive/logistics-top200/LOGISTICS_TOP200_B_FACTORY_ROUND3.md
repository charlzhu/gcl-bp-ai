# 物流域 Top200 高价值 B 题工厂化 Round3

## 一、Round3 目标

Round3 继续沿用已经验证有效的工厂化方式：

- 题族聚类
- 能力矩阵
- 批量收口
- 自动回归

本轮不是回到逐题挤牙膏模式，而是继续把剩余高价值 B 题中最容易批量推进的一批题族收进口径稳定的 A 类。

---

## 二、Round3 选择的题族

本轮共选择 `3` 个题族、`11` 条题：

1. 客户 / 项目总运量与项目地分析类（4 条）
2. 城市承运商单车均价类（5 条）
3. 异常 / 相关性分析类（2 条）

选择原因一致：

- 高频
- 业务价值高
- 数据可算性较强
- 当前收口成本低于剩余题族
- 一次补一个能力点，可以顺带吃掉一组题

---

## 三、Round3 对应的能力包

本轮实际补齐或固化的能力点主要有 `3` 组：

### 1. 历史客户 / 项目总运量能力包

支持：

- 历史累计客户总发运量
- 历史客户发运量前十排行

对应 query_key：

- `hist_customer_mw`
- `hist_customer_mw_ranking`

说明：

- 当用户明确给出客户主体但未给年份时，默认按 `2023–2025` 历史累计口径统计
- 如果仍然缺项目 / 采购方式 / 年份等稳定字段，则继续保留在 B

### 2. 城市 × 承运商单车均价能力包

支持：

- 历史某城市下，不同物流公司的平均单价 / 车

对应 query_key：

- `hist_city_carrier_avg_fee_per_trip`

说明：

- 统一按 `SUM(total_fee) / SUM(shipment_trip_count)` 计算单车均价
- 未给年份时默认按 `2023–2025` 历史累计统计

### 3. 诊断边界分流能力包

支持的不是“把诊断题硬拉进 A”，而是把边界稳定下来：

- “异常费用太高的城市有哪些”继续留在 B，并给出更明确的业务化澄清
- “路程/KM 与元/瓦显著相关性”转入 C，不再伪装成可计算查询

说明：

- 这一步本质上是在稳固 B/C 边界，而不是扩大 A 类

## 七、自动回归情况

本轮已经形成独立的 Round3 工厂化回归脚本与报告：

- 脚本：`scripts/logistics_top200_b_factory_round3.py`
- 报告：`tmp/logistics_question_bank/logistics_top200_b_factory_round3_report.json`

该脚本会：

1. 读取 Top200 正式清单
2. 扣除已经在 P1/P2、Round1、Round2 中推进进 A 或转入 C 的题
3. 自动选择 Round3 题族
4. 真实调用当前 `data-qa` 主链路
5. 输出每题状态、题族汇总和 A/B/C 变化

## 九、当前结论

Top200 高价值 B 题的工厂化推进已经从 Round1、Round2 延续到 Round3。

当前已经稳定形成：

- 题族聚类
- 能力矩阵映射
- 题族级批量收口
- 自动回归验证

Round3 说明这套方式不仅能继续把 B 题批量收进 A，也能把本来不该硬拉进 A 的题稳定地留在 B 或转入 C。下一轮不需要重起方法论，只需要继续选下一批题族、补能力包、跑回归即可。
