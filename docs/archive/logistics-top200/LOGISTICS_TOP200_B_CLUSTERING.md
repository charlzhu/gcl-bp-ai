# 物流域 Top200 高价值 B 题题族聚类

## 1. 为什么要从“单题收口”切到“题族收口”

当前 Top200 已经不是“题不够多”，而是“推进方式太散”：

- 题面很多，但业务意图高度重复
- 一次只收 1～2 条题，边际收益太低
- 实际缺的往往不是“某一道题”，而是某个共性的能力点

因此本轮先把当前 **64 条仍留在 B 的高价值题** 重组为可批量推进的题族，后续按题族、能力矩阵和批次收口，而不是继续逐题挤牙膏。

## 3. 题族组织原则

本轮题族不是按题号切，而是按：

1. 业务意图是否一致  
2. 时间 / 指标 / 维度结构是否一致  
3. 缺的能力点是否一致  
4. 补一个能力点后能否顺带吃掉一批题  

## 4. 本轮优先收口的题族

当前第一批优先收口 5 个题族：

1. 历史省份累计总费用类
2. 历史承运商年度经营KPI类
3. 2026月度承运商总运费类
4. 历史车型总车次类
5. 2026月度单瓦成本类

原因：

- 高频
- 管理价值高
- 数据可算性强
- 现有仓储查询可复用
- 一次补齐能力点后能顺带吃掉多条题

## 5. 当前仍不适合强推入 A 的题族

以下题族虽然高价值，但本轮仍不建议硬拉进 A：

- 历史线路/城市运价分析类
- 承运商成本/运费排名类
- 区域/年度运量综合与拆分类
- 客户/项目总运量与项目地分析类
- 2026系统状态/排名/填充率类
- 城市承运商单车均价类
- 异常/相关性分析类

原因分别集中在：

- query_key 仍未具备
- 统计口径仍未锁定
- 采购方式/基地映射仍缺稳定字段
- 题本身已接近分析题而不是结构化查询题

## 6. 当前结论

这轮之后，Top200 高价值 B 题已经不再是“逐题散推”状态，而是已经被组织成：

- 题族
- 代表题
- 当前阻塞
- 是否适合 round1

后续可以直接按题族推进，而不是再从单题开始。
