# 物流域题库响应策略

## 目标

本文件用于把物流域题库分层中的 **B 类（需澄清）** 和 **C 类（不支持）**，从文档判断落成系统稳定行为。

当前前提：

- 物流数据问答 MVP 核心 20 条验收题已通过
- 物流域题库总量为 `903`
- 当前题库分层为：
  - A 类：`75`
  - B 类：`356`
  - C 类：`472`
  - D 类：`0`

本文件只说明：

1. 当前 B 类的正式澄清边界
2. 当前 C 类的正式不支持边界
3. 前后端应该如何稳定表达这些结果

---

## 当前 B 类正式澄清边界

### 1. 缺少时间范围

典型问题：

- 江苏省历史发运的总费用是多少？
- 某承运商平均运费是多少？
- 某客户签收率怎么样？

当前系统行为：

- `needs_clarification = true`
- `status.code = CLARIFICATION_REQUIRED`
- 返回追问问题，要求先补充年份或统计周期

正式澄清文案方向：

- 请补充时间范围，例如 2023 年、2025 年、本月或近 30 天
- 如需查看历史累计，请明确是否按 2023–2025 历史台账统一统计

### 2. 缺少评价标准或比较口径

典型问题：

- 最近物流成本是不是变高了？
- 哪个承运商最差？
- 哪些有问题？
- 风险怎么样？

当前系统行为：

- 不直接给结果
- 先追问时间范围和评价指标

正式澄清文案方向：

- 请先明确时间范围，例如近 7 天、近 30 天、本月或今年
- 请明确指标口径，例如总费用、单瓦成本、签收率、异常率或车次

### 3. 特殊定义不明确

典型问题：

- 特殊订单有哪些？
- 特殊任务有没有异常？

当前系统行为：

- 不自行猜测“特殊”的定义
- 返回澄清问题，要求补充判定标准

正式澄清文案方向：

- 请说明“特殊”的判定标准，例如费用异常、时效异常、签收异常或指定订单类型
- 请补充时间范围，便于系统按统一口径筛选

### 4. 当前仍然是兜底式澄清的情况

以下情况当前还没有完全拆成专门模板，但系统已经会统一进入澄清：

- 题意虽像结构化查询，但缺少关键时间、指标或维度
- 问题中包含“哪个”“哪些”“多少”，但统计范围不完整
- 原始业务问法过于口语化，无法直接映射到稳定 `query_key`

## 当前 C 类正式不支持边界

### 1. 预测 / 趋势 / 波动区间

典型问题：

- 预测下个月物流费用会是多少？
- 未来 3 个月华东区域总费用波动区间是多少？

当前系统行为：

- `supported = false`
- `status.code = UNSUPPORTED_QUESTION`
- 明确提示当前属于预测分析，MVP 暂未实现

### 2. ETA / 到货时间 / 复杂时效推理

典型问题：

- 当前订单预计到达时间是什么时候？
- 某线路多久能到？

当前系统行为：

- 直接返回不支持
- 不尝试根据现有结构化字段硬推 ETA

### 3. 开放讨论 / 设计类 / 治理原则类

典型问题：

- 若某个任务被拆成很多次派车，系统做均值分析时应如何处理？
- 应遵循什么原则？
- 如何设计一套异常识别规则？

当前系统行为：

- 直接返回不支持
- 不把讨论题伪装成结构化结果

### 4. 额外费用项目 / 原因 / 明细

典型问题：

- 额外费用分别是什么项目？
- 为什么会产生这些额外费用？
- 额外费用明细有哪些？

当前系统行为：

- 直接返回不支持
- 明确提示当前 MVP 仅支持额外费用总额

---

## 当前已固化到系统行为的高频模式

已正式下沉到 planner 的模式包括：

- 预测 / 趋势 / 波动区间类不支持
- ETA / 到达时间类不支持
- 开放讨论 / 治理原则 / 方案设计类不支持
- 额外费用项目 / 原因 / 明细类不支持
- “最近 / 最差 / 异常 / 哪些有问题”类高频模糊问法先澄清
- 缺少时间范围的费用 / 运费 / 签收率 / 元瓦类问题先澄清
- “特殊订单 / 特殊任务”定义不明时先澄清

## 前后端统一展示口径

### B 类（需澄清）

后端输出：

- `needs_clarification = true`
- `clarification_questions`
- `status.code = CLARIFICATION_REQUIRED`

前端展示建议：

- 主标题：`请补充查询条件`
- 明确提示：当前问题还不够明确，系统暂不直接计算
- 直接列出追问问题

### C 类（不支持）

后端输出：

- `supported = false`
- `status.code = UNSUPPORTED_QUESTION`
- `answer_summary = 当前问题暂不支持...`

前端展示建议：

- 主标题：`当前问题暂不支持`
- 展示原因说明
- 不伪装成成功态
