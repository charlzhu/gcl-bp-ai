# LOGISTICS_B_LONG_CLARIFICATION_ROUND2.md

## 一、目标

本轮继续推进 `B-长期澄清池 Round2`，重点不是把问题直接推进进 A，而是让系统更稳定地识别：

1. 当前问题缺了什么口径；
2. 应该追问什么内容；
3. 追问时如何更贴近业务表达；
4. 同时保持最终边界仍由规则层裁决。

本轮继续坚持：
- 规则层负责最终 `clarification / unsupported / success` 边界；
- LLM 只做缺口径识别和追问候选生成；
- 不新增 query_key；
- 不放松 B/C 边界。

## 四、Round2 具体增强了什么

### 1. 状态风险类

代表题：
- `Q094`~`Q098`
- `Q228`

当前系统不再只给泛化追问，而会更明确地追问：
- 风险按什么口径定义
- 看当前在途、近 30 天还是全年正式任务

### 2. 数据质量类

代表题：
- `Q273`
- `Q276`
- `Q277`
- `Q278`
- `Q282`
- `Q283`
- `Q284`
- `Q289`
- `Q290`

当前系统会更明确地区分：
- 问的是问题数量、问题率，还是问题明细清单
- 是否还要按承运商、状态、采购方式继续拆分

### 3. 采购方式与特殊业务口径类

代表题：
- `Q265`
- `Q266`
- `Q285`
- `SQ511`
- `SQ513`

当前系统会更明确地追问：
- 具体比较的是任务量、发运量、平均装车数，还是总运费/运费差异
- 是否只统计已打标的正式系统任务

### 4. 高运费项目地与状态拆分类

代表题：
- `SQ468`~`SQ480`
- `Q271`
- `SQ581`

这批题现在也正式纳入 Round2，不再停留在规则模板之外。

- 规则层锁住边界；

## 六、下一步建议

下一步先不要扩新主线，优先考虑：
