# LOGISTICS_B_LONG_CLARIFICATION_ROUND4

## 一、目标

`B-长期澄清池 Round4` 的目标不是把问题强行收进 `A`，而是继续把**本来就应该先澄清**的问题做成更稳定、更业务化的追问流程。

本轮继续坚持两条边界：

1. 规则层负责最终边界裁决；
2. LLM 只做缺口径识别和业务化追问候选生成。

---

## 二、本轮范围

本轮继续只覆盖 `B-长期澄清池` 里仍适合工厂化治理的结构化题型，主要包括：

- 季度区域运费 / 单瓦运输成本类
- 运输方式平均单瓦成本类
- 特殊业务口径平均单瓦成本类
- 2026 系统状态 / 数据质量高频结构化问题

本轮正式澄清类别为：

- `quarter_area_metric_scope`
- `transport_unit_fee_scope`
- `procurement_metric_scope`
- `parse_status_scope`
- `state_breakdown_scope`
- `state_ranking_scope`
- `data_consistency_scope`
- `task_split_scope`

## 四、本轮规则增强点

### 1. 季度区域统计类

当前系统可以更稳定识别：

- `2023年一季度各区域运费分别是多少？请按区域排序展示。`
- `2024年二季度各区域单瓦运输成本分别是多少？`

当前先追问：

- 是否统一只按 2023–2025 历史台账口径统计
- 区域排序按指标排序还是按固定区域顺序展示

### 2. 运输方式平均单瓦成本类

当前系统可以更稳定识别：

- `2024年公路运输的平均单瓦成本是多少？`
- `2026年1-2月铁路运输的平均单瓦成本是多少？`

当前先追问：

- 平均单瓦成本是总运费除总瓦数，还是逐条记录单瓦成本再平均
- 是否把额外费用计入分子

### 3. 特殊业务口径平均单瓦成本类

当前系统可以更稳定识别：

- `2025年经营计划场景下的平均单瓦成本是多少？`
- `2026年1-2月辅料送样场景下的平均单瓦成本是多少？`

当前先追问：

- 是否只统计已有场景标签的正式任务
- 单瓦成本是否把额外费用一起计入

### 4. 2026 状态 / 数据质量结构化问题

当前系统可以更稳定识别：

- `2026年派车任务的送货单解析状态分布（0/1/3/4）分别是多少？`
- `2026年allocate_task各状态的数量分别是多少？`
- `2026年哪些省份的PREASSIGN待派车任务最多？`
- `2026年是否存在同一车牌在同一天关联多个不同的派车任务？`
- `2026年单个ship_task被拆分为派车任务最多的是哪些任务？`

当前先追问：

- 统计对象是哪张任务表
- 结果是看数量、占比，还是异常明细
- “最多”“拆分最多”按什么口径判断

## 五、LLM 在 Round4 中的使用方式

Round4 继续坚持：

- LLM 可以做：
  - 缺口径识别
  - 业务化追问候选生成
- LLM 不可以做：
  - 最终边界裁决
  - 把 `clarification` 改成 `success`
  - 把 `clarification` 改成 `unsupported`

本轮 live 样本里出现了 `1` 次 `provider error`，因此最终统计是：

- `llm_invoked_total = 12`
- `assist_applied_total = 11`
- `provider_mode_breakdown = {"live": 11, "rule_only": 35, "error": 1}`

这说明当前 LLM 澄清辅助已经能稳定提升追问质量，但仍必须保留规则模板兜底。

---

## 六、当前结论

`B-长期澄清池 Round4` 完成后，说明当前长期澄清治理仍然值得继续推进，但后续不应再按同样体量无限扩大。

当前更适合的做法是：

1. 先同步项目级状态文档到 `Round4`；
2. 再评估剩余 `30` 条是否继续做 `Round5`；
3. 如果剩余题开始明显偏向边界解释或开放诊断，再考虑转入 `C-边界观察池`。
