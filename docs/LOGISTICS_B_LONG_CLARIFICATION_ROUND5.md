# B-长期澄清池 Round5 收尾报告

## 一、结论

`B-长期澄清池 Round5` 已完成剩余 30 条治理覆盖。本轮不是把 B 类强行推进为 A，而是按当前真实主链路重新裁决：

- 仍应澄清的题保留在 B，并补齐更业务化追问。
- 当前已能稳定查询的题推进到 A。
- 实际属于系统策略、仓库维度不可靠等边界外问题转入 C。

- 本轮处理：`30`
- 保留 B：`20`

- 转入 C：`7`
- B-长期澄清池 Round1-5 剩余未覆盖：`0`

## 三、LLM 使用边界

本轮继续保持 LLM 只做辅助理解，不做最终边界裁决。

- LLM 可做：缺口径识别、追问候选生成、业务化表达优化。
- LLM 不可做：把 B 改成 A、把 C 改成 B/A、生成 SQL、直接查数、替代 planner。
- 最终分类仍由规则层和现有 data-qa 主链路裁决。

## 四、已增强的长期澄清模式

- 运输口径字段别名与跨年对比口径。
- 产生原因分布类问题的原因字段与统计口径。
- 合同号对应多承运商时的主口径选择。
- 运输距离、单瓦价、车次、发运量等指标口径。
- 短上下文追问类问题，例如“分别是多少”。
- 解析失败、司机身份一致性等数据质量/治理类问题。

## 五、转入 C 的边界

- 仓库维度当前不是一期可靠统计维度。
- 系统应如何追问、如何拆解、如何输出、如何解释字段等问题属于系统策略设计，不是物流结构化数据问答。

## 六、当前判断

B-长期澄清池已经完成 Round1-5 阶段性治理覆盖。下一步不建议继续围绕同一池做 Round6，而应转入 `C-边界观察池`，重点固化拒答理由和业务可理解解释。
